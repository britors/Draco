# Internacionalização

O Draco traduz a própria interface para **inglês** (`en`, idioma de reserva) e **português do
Brasil** (`pt-BR`). A tradução é local e funciona offline: os catálogos são módulos JavaScript
empacotados em `frontend/dist` e embutidos no binário Tauri, então o RPM, o DEB e o instalador
Windows os incluem sem arquivos extras.

## O que nunca é traduzido

SQL, nomes de schema/tabela/coluna, resultados de query e qualquer texto vindo do PostgreSQL
(erros, notices, DDL). Mensagens de erro do banco chegam ao frontend sem `key` e são exibidas
exatamente como o servidor as enviou.

## Escolha do idioma

`resolveLocale` lê `navigator.languages`, que no WebKitGTK reflete o locale do sistema (`LANG`,
`LC_ALL`). Qualquer variante de português (`pt`, `pt-PT`, `pt_BR.UTF-8`) usa o catálogo `pt-BR`;
os demais idiomas caem em inglês. O idioma é aplicado na carga da página e define
`<html lang>`.

## Catálogos e chaves

- `frontend/dist/locales/en.js` e `frontend/dist/locales/pt-BR.js` exportam um objeto
  congelado `chave → mensagem`.
- As chaves são estáveis e agrupadas por superfície: `nav.*`, `connections.*`,
  `connectionForm.*`, `dialog.*`, `error.*` etc. Renomear uma chave é uma mudança de contrato,
  porque o backend também envia chaves `error.*` (ver
  [`tauri-application-contract.md`](../architecture/tauri-application-contract.md#envelope-de-erro)).
- Parâmetros usam `{nome}`: `t('greeting', { name })`.
- Plurais usam um objeto com as categorias do `Intl.PluralRules` (`one`, `other`, …) e,
  opcionalmente, formas exatas como `'=0'`. No português o CLDR trata 0 como singular, por isso
  `connections.count` usa `'=0': 'nenhuma conexão'`. O número é formatado no locale
  (`1.500 conexões`).
- Chave ausente no catálogo do idioma cai no inglês; ausente nos dois, aparece a própria chave.

## Usando no frontend

- HTML estático: `data-i18n="chave"` (texto), `data-i18n-title`, `data-i18n-aria-label` e
  `data-i18n-placeholder`. Texto ao lado de um `<input>` dentro de `<label>` vai num `<span>`
  próprio, porque a tradução substitui o `textContent` do elemento.
- JavaScript: `t('chave', params)`; o resultado entra no DOM somente com `textContent` ou
  `setAttribute`.
- Erros da bridge: `errorMessage(error, t, chaveDeReserva)`.

## Como contribuir com traduções

1. Adicione a chave nos **dois** catálogos, com os mesmos `{placeholders}`.
2. Use a chave no HTML ou no `app.js`.
3. Rode `cd frontend && npm run check && npm test`. O `tests/i18n.test.mjs` falha se os
   catálogos tiverem chaves diferentes, se um placeholder divergir, se um plural não tiver
   `other` ou se o HTML/`app.js` usar uma chave inexistente.

Para um idioma novo, crie `locales/<locale>.js` com todas as chaves de `en.js` e registre-o em
`CATALOGS` (`i18n.js`).

## Cobertura atual

Traduzidos: shell, navegação, títulos das páginas, controles da janela, estado do backend,
diálogos padrão, tela e formulário de conexões, e os erros genéricos da bridge. O `.desktop` e o
AppStream têm nome, resumo, descrição e recursos em pt-BR.

Ainda em inglês (próximas etapas da issue #118): Explorer, Programming/GitHub, Editor SQL e
resultados, Dashboard, Administração, backup/restauração, Assistente, Preferências, paleta de
comandos e as mensagens de validação (`invalid_input`) do backend.
